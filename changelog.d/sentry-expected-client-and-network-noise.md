**Client/network-lifecycle noise no longer burns Sentry quota**: `starlette.requests.ClientDisconnect` (the client walked away mid-body-read; always unhandled, never a proxy defect) is now dropped in `_sentry_before_send` only when *every* leaf exception in the event is ClientDisconnect — a mixed `ExceptionGroup(ClientDisconnect, RuntimeError)` still reports, since the `RuntimeError` is a genuine proxy-side failure riding alongside the disconnect. Mid-stream `httpx.TransportError`s (`RemoteProtocolError`, `ReadTimeout`, `ReadError`, ...) are now classified at the actual upstream call boundary: `AnthropicClient.complete`/`stream` wrap a transport failure from the real Anthropic connection into a distinct `AnthropicUpstreamTransportError`, which the streaming (`_build_error_event`), non-streaming (`_handle_anthropic_error`), AND the streaming completion-webhook/request-log status classification now all downgrade to 502/503 `api_connection_error` — matching the existing `AnthropicConnectionError` handling instead of falling through to an unclassified proxy 500. A raw `httpx.TransportError` from anywhere else (e.g. a policy's own outbound HTTP call) is not this type and stays on the error-level internal path. Malformed JSON in an incoming request (a client error, already returned to the client as an HTTP 400) now logs at warning instead of error. Genuine proxy bugs mid-stream still log at error and still report.
